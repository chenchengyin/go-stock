# 超短情绪短线避坑说明

## 功能定位

`超短情绪` 是 Flutter App 里的短线盯盘辅助页面，核心目标是帮助超短交易在出手前先判断市场情绪和风险环境。

它不是确定性的买卖信号，也不直接替代交易决策。页面更适合回答这几个问题：

- 今天短线环境适不适合出手。
- 当前市场是普涨、分歧、退潮，还是冰点。
- 炸板、跌停、空头异动这些风险是否已经变重。
- 如果要参与，仓位应该偏主动还是偏防守。

## 当前页面入口

Flutter App 底部 Tab 顺序为：

1. `盘达`
2. `超短情绪`
3. `市场快讯`
4. `我的`

`策略吧` 入口目前只是暂时隐藏，业务代码和接口没有删除。

## 数据来源

当前 v1 已接入的真实数据包括：

| 指标 | 来源 | 用途 |
| --- | --- | --- |
| 上涨家数、下跌家数 | 市场统计接口 | 计算红盘率和市场宽度 |
| 涨停数、跌停数 | 市场统计接口 | 判断涨跌停质量和退潮风险 |
| 盘中异动 | 东方财富异动接口 | 统计多头异动、空头异动、打开涨停板 |
| 涨停热度 | 涨停热度接口 | 提取主线板块、最高连板、3 板以上数量、封板数量 |
| 两市成交额 | 东方财富指数实时行情 | 计算指数量能和量能分 |

当前 v1 对量能的处理：

| 指标 | 当前状态 | 说明 |
| --- | --- | --- |
| 实时两市成交额 | 已接入 | 使用上证指数和深证成指成交额聚合 |
| 量能分 | 已接入 | 根据两市成交额和盘中预估全天成交额打分 |
| 兜底机制 | 已接入 | 实时接口失败时优先使用缓存，缓存也没有时才回落到 50 分 |

## 默认评分权重

总分为 0-100 分，当前默认权重如下：

| 维度 | 权重 | 说明 |
| --- | ---: | --- |
| 宽度情绪 | 25 | 主要看红盘率，判断赚钱效应扩散程度 |
| 涨跌停质量 | 25 | 主要看涨停、跌停、炸板率 |
| 连板生态 | 20 | 主要看最高连板和 3 板以上数量 |
| 异动强弱 | 15 | 多头异动与空头异动对比 |
| 板块主线 | 10 | 是否有清晰主线，以及主线热度 |
| 指数量能 | 5 | 看两市成交额和盘中预估全天成交额 |

这套权重偏向 `中等偏避坑`：不是只看高分追强，而是会对炸板、跌停、空头异动这些短线杀伤力更大的信号做额外惩罚。

## 避坑逻辑

除了基础加权分，系统还会对高风险信号做扣分或降级处理：

| 风险信号 | 处理方式 |
| --- | --- |
| 炸板率较高 | 扣分，并限制过高的参与建议 |
| 跌停数量较多 | 提高风险等级，降低动作建议 |
| 空头异动多于多头异动 | 扣分，并提示空头风险 |
| 无明显主线 | 风险信号中提示主线不清晰 |

因此，页面里可能出现这种情况：部分指标看起来不错，但总建议仍然偏谨慎。这通常是因为避坑因子触发了。

## 分数和动作解释

页面会输出：

- `score`：综合情绪分。
- `phase`：市场阶段，例如 `活跃偏分歧`、`退潮防守`。
- `action`：动作建议，例如 `轻仓参与`、`谨慎观察`。
- `riskLevel`：风险等级。
- `suggestedWeight`：参考仓位，例如 `2-4成`。

这些结论是规则模型生成的，不是 AI 预测，也不是历史回测保证。实际交易仍需要结合个股位置、题材强度、买点、卖点和个人交易纪律。

## 接口说明

Flutter App 调用的后端接口：

```http

```

返回核心字段：

```json
{
  "score": 56,
  "phase": "活跃偏分歧",
  "action": "轻仓参与",

  "suggestedWeight": "2-4成",
  "mainTheme": "芯片",
  "dashboard": [],
  "components": [],
  "riskSignals": []
}
```

## 已知限制

- 两市成交额使用免费实时行情接口，可能存在偶发失败或延迟；失败时会优先使用进程内缓存。
- 非交易时段展示的数据取决于上游接口是否仍返回当日数据。
- 当前权重是经验规则，尚未做历史回测校准。
- 页面用于风险识别和交易前冷静判断，不应单独作为买卖依据。

## 后续增强方向

后续可以继续增强量能质量：

1. 成交额较昨日同时间变化。
2. 最近 5 日成交额均值对比。
3. 指数涨跌幅和量价配合。
4. 情绪分历史曲线。
5. 盘中高风险事件时间线。

补充历史量能对比后，`超短情绪` 对早盘缩量冲高、午后放量杀跌、弱反弹等场景的识别会更稳定。
