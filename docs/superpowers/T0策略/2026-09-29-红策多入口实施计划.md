# 红策多入口形态汇总 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 旧红策高开分支保持原样；从完整 Gob 基础池独立接入两种已确认低开形态，并使未来规则能各自定义任意 T0 开盘区间。

**Architecture:** 保留主板筛选链与旧 `filterRedT0Results`；新增很薄的 Gob 红策规则列表（代码内人工启用）、共享匹配入口和独立快照，在红策响应处按股票日合并。入场判定与 T+1 统计分离；不做规则 DSL、可视化配置器或全局红策开盘门槛。

**Tech Stack:** Go、现有 `candlepattern`、Gob 日线缓存、GORM/SQLite、Flutter。

**Spec:** [红策多入口设计](2026-09-29-红策多入口设计.md)；[开发测试契约](2026-09-29-红策多入口测试用例.md)。

## Global Constraints

- 直接在 `dev` 实施，不创建分支、不推送/部署；仅提交本功能文件，保留工作区已有 Gob、数据库、报告等改动。提交信息沿用项目中文习惯。
- `filterOpenGap(..., 0.01, 3.0)`、主板归档、旧红策 T0 参考统计、其他策略入选语义不改。每条 Gob 规则自行判断**未舍入**的 T0 gap；测试注入 +5% 规则以发现隐藏的全局门槛。
- 选股只读 T0 及以前的可用开盘/历史 K 线，不读取 T0 收盘或 T+1 来决定入选。历史 `daily_open` 仅是代理值；实时无确认 Open 不以现价/日线 Open 顶替。
- 先写最小失败测试、确认失败、再写代码、跑针对性测试。每个任务验证后独立提交；每次 `git add` 指定文件，不 stage 整个工作区。
- 若股票适用跌停价无法可靠核验，拒绝正式入选并标不完整；不能以普通主板 10% 一刀切。

## Review Focus

1. Gob 独立来源能否在主板结果为空、主板无归档时仍返回；预热/正式/历史是否走同一规则语义。
2. 旧响应作用域在 `selectT0ResultsForModule` 和 `writeScopedT0ResponseWithContext` 各处理一次，新增合并不能二次过滤掉独立命中。
3. 快照优先级、缓存完整性与权限，尤其不可把日线 Open 回填成实时成交价。
4. 新 T+1 胜率与旧 T0 胜率在存储、JSON、页面上各自有清楚口径。

## Task 1：两种 Gob 规则的最小匹配核

**流程：** 完整 Gob 股票日线 → 截至 T-1 的历史 → 原有 K 线分类 → 最近收盘涨停锚点/回撤 → 规则自己的原始 gap 与跌停开盘核验 → 命中元信息。

**伪代码：**

```text
for stock in GobStocks:
  hist = bars strictly before T0
  for rule in enabledGobRedRules:  // 仅 A/B，测试可注入其它规则
    if rule.MatchHistory(hist) and validConfirmedOpen(stock):
      gap = (open / prevClose - 1) * 100 // 不舍入
      if rule.MatchOpen(gap, stockLimitContext): append RuleHit
```

**注意：** 不复用旧 T0 reference 引擎（它只支持 T-3～T-1 和 T0 收盘统计）；复用 `candlepattern` 分类及现有日线结构。规则用稳定键/版本、名称、评判时点和两个小匹配函数即可；不要做通用 AST。特殊股票价格限制若没有可靠数据来源，必须明确不完整；这一步核对现有数据字段和历史报告边界。

**Files:**

- Create: `backend/flutter_api/t0_red_gob_rules.go`
- Modify: `backend/flutter_api/t0_selection.go`（仅结果字段/必要类型）
- Test: `backend/flutter_api/t0_red_strategy_test.go`

## Task 2：预热与正式选股接入，旧分支去重合并

**流程：** 一次完整 Gob 缓存 → 主板原链 + Gob 独立链并行取候选 → 旧红策与独立规则按交易日+代码合并 → 作用域/展示一次 → 其他模块保持原链。

**伪代码：**

```text
daily, stocks = loadGobForDate(date)
main = runExistingMainFilter(stocks, daily) // 空也保留 Gob 数据
independent = matchGobRedRules(stocks, daily, opens, enabledRules)
if module == red: response = mergeUnique(filterRed(main), independent)
else: response = existingModuleSelection(main)
```

**注意：** 现有主板函数在成交额/开盘过滤为空时提前报错；红策不能随之退出。`RunT0Selection` 对外返回形状不变。`writeScopedT0ResponseWithContext` 目前会再次筛选，需让独立结果只聚合一次，避免重复/丢失；保持已有鉴权。预热零 gap 仅是占位，不可生成正式命中。

**伪代码：**

```text

aggregate(sampleN, positiveN, targetN, average, coverage)
```
