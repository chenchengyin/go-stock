# 红策多入口开发测试用例（契约）

对应设计：[2026-09-29-红策多入口设计.md](2026-09-29-红策多入口设计.md)。测试先于实现；使用合成日线、临时缓存/SQLite，不读写本地 `data/stock.db`。历史 23/19 仅为可选的完整 Gob 回放核对，不代替确定性的单元测试。

## 规则与入场

| ID | 测试文件 | 输入 | 预期 |
| --- | --- | --- | --- |
| 规则-RULE-001 | `backend/flutter_api/t0_red_strategy_test.go` | 完整 Gob 池中 A=`MYIN,DT,DT`、B=`MYIN,MYIN,DT`，均不在主板结果，最近收盘涨停位于 T-2～T-10、T-1 低于锚点、T0 原始开盘涨幅 -5% | 两股按各自规则入选红策；主板结果不增股；命中含稳定规则键/版本、名称、`T+1_close` 与开盘来源。 |
| 规则-RULE-002 | 同上 | 仅有盘中触板收盘未涨停、最近收盘涨停分别位于 T-1/T-11，或已有更近一次收盘涨停位于有效区间外 | 均不以更早/破板日绕过“最近一次收盘涨停 2～10 个交易日”。 |
| 规则-RULE-003 | 同上 | A/B 形态满足但 T-1 收盘不低于锚点；或 T-3/T-2/T-1 任一标签不符 | 不入选；标签由现有 `candlepattern` 分类结果决定。 |
| 规则-RULE-004 | 同上 | 原始 gap 恰为 -9.85%、恰为 -3%、在两端内、四舍五入后看似在区间内但原始值在区间外 | 仅原始值严格处于开区间的样本入选；展示舍入不改变判定。 |
| 规则-RULE-005 | 同上 | 普通主板、不同涨跌停幅度股票分别以当日跌停价开盘；价格限制信息无法可靠确定 | 前两者排除；后一者标数据不完整，不猜测为可买入。 |
| 规则-RULE-006 | 同上 | 缺 T-1 前收盘、足够历史 K 线、有效 T0 开盘价；T0 当日日线含未来收盘信息 | 缺失者不正式入选；修改 T0 收盘/T+1 数据不影响入选。 |
| 规则-RULE-007 | 同上 | 仅在测试注入一个原始 gap +5% 的 Gob 规则，主板区间仍为 0.01%～3% | 红策可命中该测试规则；主板、A/B 命中均不变，证明红策无全局开盘门槛。 |
| 规则-RULE-008 | 同上 | 同一股票日同时命中旧分支与独立分支，或命中独立分支及测试注入规则 | 红策只有一张卡，全部命中键/名称保留，计数只加一；排序稳定。A/B 的 T-2 标签互斥，不构造伪重叠样本。 |

## 来源、时序、归档与接口

| ID | 测试文件 | 输入 | 预期 |
| --- | --- | --- | --- |
| 入口-ENTRY-001 | `backend/flutter_api/t0_red_strategy_test.go` | 相同主板结果与日线，改造前后的旧红策；同时请求主板/紫策/蓝策/金策 | 旧分支命中及 T0 统计不变；其他模块无 Gob 独立增股。 |
| 入口-ENTRY-002 | `backend/flutter_api/t0_red_strategy_test.go` | 主板日线过滤或开盘过滤后为 0，Gob 独立规则有命中 | 红策仍返回该命中；主板依旧返回原空结果/错误语义。 |
| 入口-ENTRY-003 | `backend/flutter_api/t0_selection_cache_test.go` | 完整 Gob 缓存，09:25 前；候选满足 A/B 前置条件但没有已确认开盘 | 可见“待竞价候选”；不显示正式胜率/买入命中，不写正式快照。 |
| 入口-ENTRY-004 | `backend/flutter_api/t0_red_strategy_test.go` | 当日实时已确认 Open、实时开盘缺失、历史 T0 日线 Open 三组 | 分别标 `realtime_open`、未确认/不入选、`daily_open`；实时路径不以现价或缓存日线替代开盘。 |
| 入口-ENTRY-005 | `backend/flutter_api/t0_red_strategy_test.go` | 无红策权限的历史/实时/预热请求 | 所有路径均按现有 `radar.red_strategy` 权限拒绝，不透出候选和独立快照。 |
| 归档-ARCH-001 | `backend/flutter_api/t0_red_strategy_test.go` | 同日正式命中后重复刷新，第二次行情缺失；主板归档存在或不存在 | 独立快照原子保存、幂等保留有效开盘事实；主板归档仍只含主板结果。 |
| 归档-ARCH-002 | 同上 | 独立快照存在但没有主板归档；仅有完整历史 Gob、没有任何快照；Gob 池或日期不完整 | 前两者可单独显示独立命中并标相应来源；不完整源不能伪装完整总数，旧来源缺失单独标记。 |
| 归档-ARCH-003 | 同上 | 同一历史日同时有实时快照与事后 `daily_open`，或旧版本规则快照 | 优先保留实时开盘来源；按规则版本解释旧结果，不静默用新规则或代理价覆盖。 |
| 入口-ENTRY-006 | `backend/flutter_api/t0_red_strategy_test.go` | Gob 解码失败、股票池不完整、部分股票无日线、快照写入失败 | 响应明确分支状态/缺失数量/“未归档”；能用的旧分支保留，不能宣称红策总列表完整。 |
