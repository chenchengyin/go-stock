# T0 前置形态参考库统一架构设计

## 背景与目标

当前 T0 形态库 `t0_pattern_stats` 以 `(pattern, window)` 为唯一键，适合保存 `YX|ZT|ZT` 这类固定 K 线标签序列，但无法完整表达以下规则：

- T-2 振幅大于或等于 8%；
- T-1 开盘涨幅大于或等于 8%；
- T-1 收盘涨停且不是一字涨停；
- 多个 T-3、T-2、T-1 数值条件的组合。

本功能将形态库升级为统一的 **T0 前置形态参考库**。所有规则都只描述 T-3、T-2、T-1 的前置条件，并以 T0 竞价买入后的结果作为统计目标，统一支持：

1. 普通 K 线标签形态；
2. 涨停接力形态；
3. 带开盘涨幅、振幅、均线等数值谓词的组合形态；
4. 后续新增的 T-3～T-1 条件，而不再为每类形态修改数据库结构。

同时保留现有旧逻辑，使已有归档 JSON、`形态`、`买入信号`、颜色和页面行为可以继续工作。

## 非目标

- 不删除或破坏现有 `t0_pattern_stats` 表。
- 不改变现有普通形态的 `BuySignal` 计算口径。
- 不把所有胜率达到 65% 的规则自动变成红色或深红色；优先级与颜色是两个独立概念。
- 不把任意 Go 代码或不可控表达式存进数据库执行。
- 不在前端重新计算 T-3～T-1 条件；规则匹配和统计由后端统一完成。
- 第一阶段不要求把所有非 K 线数据都纳入规则，只覆盖日线 OHLCV、成交额及其可推导指标。
- 不立即用新库替换旧库；旧库和新库需要经过双读/回退验证后再切换。

## 权限

不新增权限。形态原始数据、规则和统计属于后端内部分析数据；结果沿用现有 T0 策略模块的访问控制。已有主板策略、红策、紫策和蓝策权限逻辑不因本功能改变。

## 页面 / 接口（用户可观察行为）

### 现有字段保持兼容

现有接口继续返回以下字段，旧归档可以继续读取：

- `形态`；
- `形态样本数`；
- `形态达标率(%)`；
- `形态真亏率(%)`；
- `买入信号`；
- `命中条件`；
- `重点标红`。

旧字段仍由旧形态统计适配器提供，不能因为新规则没有普通 `pattern` 字符串而置空或改变颜色。

### 新增 T0 参考信息

统一规则命中后，结果可以附加以下可选字段：

```text
T0参考形态命中      [{rule_key, name, research_tier, strict_win_rate, sample_count, deep_red}]
T0参考最高等级      string       // A / B / normal
T0参考严格胜率(%)   number       // 最高等级规则的统计值
T0参考样本数        number       // 最高等级规则的样本数
```

默认最多返回命中规则中排序靠前的 3 条，完整规则明细由后端内部保留；没有命中规则时返回空数组或省略可选字段。新字段只用于说明和排序，不覆盖旧的 `买入信号`。

### 优先级行为

所有策略结果都可以获得同一套 T0 参考研究等级：

- A 级：严格胜率 ≥ 65%，样本数 ≥ 20；
- B 级：严格胜率 ≥ 65%，样本数为 10～19；
- 普通参考：已入库但未达到上述优先条件；
- 无参考：没有命中启用规则。

研究等级由统计结果计算，人工调整顺序使用规则表中的 `manual_rank`，两者不混为同一个字段。参与策略列表排序时，A 级先于 B 级，再按 `manual_rank`、现有信号、标签、赚率和竞价涨幅排序。研究等级不自动改变普通形态信号颜色，也不覆盖现有“两连涨停 + T-1 非一字 + T-1 开盘涨幅≥3%”的深红逻辑。

深红是人工明确指定的标记，不由“样本少但胜率高”的通用阈值自动推导。当前深红保留三套明确逻辑：`任意K线＋涨停＋跌停`、`T-2 低开 + T-1 开盘涨幅≥3% + T-1 振幅≥8%`，以及“两连涨停 + T-1 非一字 + T-1 开盘涨幅≥3% + T0 竞价”。`T-2 振幅≥8% + T-1 开盘涨幅≥8% + T-1 振幅<4%` 作为次级候选继续统计但暂不标深红；`ZT|DYIN|DT`、`DYIN|YX|MYIN` 等其他候选同样只进入形态库研究。规则表通过 `deep_red` 保存形态库规则的人工选择；内置展示规则通过显式深红匹配函数维护。

## 架构与数据

### 总体数据流

```text
本地日线 Gob
    ↓
T0 原始观察构建器
    ↓
保存 T0 + T-3/T-2/T-1 原始样本
    ↓
通用规则匹配器
    ├── 普通 K 线序列规则
    ├── 接力规则
    └── 数值条件组合规则
    ↓
规则统计聚合器
    ↓
T0 参考规则统计库
    ↓
T0 选股结果增强与优先排序
```

### 1. 原始观察表 `t0_reference_observations`

该表是后续重新分析的事实层。同一源数据版本下，每只股票、每个交易日最多一条记录；源数据修复时可以保留多个版本，但同一股票日最多一个活动版本。不能只保存已经命中某个形态的股票。

建议字段：

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `trade_date` | T0 交易日 |
| `stock_code` | 股票代码 |
| `t0_prev_close` | T0 前收盘价 |
| `t0_open` | T0 日线开盘价 |
| `t0_high` | T0 最高价 |
| `t0_low` | T0 最低价 |
| `t0_close` | T0 收盘价 |
| `t0_volume` | T0 成交量 |
| `t0_amount_yi` | T0 成交额，亿元 |
| `t0_open_gap` | T0 日线开盘相对前收盘的涨幅 |
| `entry_price` | 实际竞价买入价 |
| `entry_gap` | 实际买入价相对 T0 前收盘的涨幅 |
| `entry_source` | `daily_open` 或 `auction_0925` |
| `t0_pnl` | `(t0_close-entry_price)/entry_price*100` |
| `data_status` | `complete` 或 `incomplete` |
| `universe_batch` | 股票池快照批次 |
| `source_batch` | 由源 Gob/缓存版本确定性生成的数据批次 |
| `source_hash` | 该股票日线快照哈希 |
| `is_active` | 同一股票日的当前有效版本 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

历史数据中 `entry_source=daily_open`，`entry_price=t0_open`；实时数据只有在 09:25 竞价价确认后，才可以使用 `entry_source=auction_0925` 写入完整交易观察。日线开盘价和实际买入价必须分开保存。

原始观察版本不可覆盖。唯一约束为 `(trade_date, stock_code, source_batch)`；同时建立 `(trade_date, stock_code)` 查询索引，并通过应用逻辑或 SQLite 部分唯一索引保证同一股票日最多一个 `is_active=1` 版本。

原始观察不按当前 `0.01%～2%` 竞价条件裁剪，所有具有完整 T0 和前三根历史日线的股票日都保存。这样未来调整竞价区间、收益阈值或交易退出规则时，不需要重新抓取行情。

观察数据必须记录 `universe_batch` 和 `source_batch`。当前数据若来自本地现有股票池，只能声明为该股票池范围内的历史样本，不能标称为完整全市场历史样本。

### 2. 前置 K 线表 `t0_reference_bars`

每条原始观察保存 T-3、T-2、T-1 三根日线，使用偏移量而不是固定列名，便于将来扩展 T-4、T-5。

建议字段：

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `observation_id` | 关联原始观察 |
| `offset` | `-3`、`-2`、`-1`，未来可扩展 |
| `bar_date` | K 线日期 |
| `prev_close` | 该 K 线前收盘价，用于计算开盘/收盘涨幅 |
| `open` | 开盘价 |
| `high` | 最高价 |
| `low` | 最低价 |
| `close` | 收盘价 |
| `volume` | 成交量 |
| `amount_yi` | 成交额，亿元 |
| `source_batch` | 来源数据批次 |

唯一约束：`(observation_id, offset)`。索引：`(observation_id, offset)`；按日期和股票查询时通过原始观察表的 `trade_date`、`stock_code` 索引定位。

原始 OHLCV 是事实来源。涨停、非一字、K 线类型、振幅和开盘涨幅等均在规则匹配时按统一函数重新计算，避免把过期的派生字段当成事实。

### 3. 通用规则表 `t0_reference_rules`

规则表描述“什么样的 T-3～T-1 样本属于该形态”，不保存具体股票日数据。

建议字段：

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `rule_key` | 规范化后的唯一规则键 |
| `rule_kind` | `sequence` 或 `condition`，仅用于分类和展示 |
| `name` | 人可读名称 |
| `lookback_start` | 默认 `-3` |
| `lookback_end` | 默认 `-1` |
| `definition_version` | 条件 JSON 版本 |
| `condition_json` | 只描述 T-3～T-1 的统一条件 AST |
| `entry_json` | 只描述 T0 竞价/买入条件 |
| `manual_rank` | 人工排序值，越小越靠前 |
| `min_samples` | 最低有效样本数 |
| `deep_red` | 是否为人工筛选的深红候选；不由样本门槛自动推导 |
| `enabled` | 是否启用 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

`rule_key` 必须由规范化后的 `condition_json`、`entry_json` 和 `definition_version` 生成。条件顺序、空格和浮点格式不同不能产生重复规则。规则修改不能覆盖旧定义，必须生成新的规则版本，以便旧统计仍能追溯到原条件。

`rule_kind` 只是分类，不代表两套匹配器。普通序列和数值条件最终都编译为同一种统一条件 AST。规则执行只允许使用注册过的字段和运算符，例如 `eq`、`lt`、`lte`、`gt`、`gte`、`between`、`and`、`or`。

普通形态示例：

`condition_json`：

```json
{
  "sequence": ["YX", "ZT", "ZT"]
}
```

`entry_json`：

```json
{
  "field": "entry_gap",
  "op": "between",
  "min": 0.01,
  "max": 2.0,
  "inclusive": true
}
```

数值条件示例：

`condition_json`：

```json
{
  "all": [
    {"field": "t-2.close_type", "op": "eq", "value": "ZT"},
    {"field": "t-1.close_type", "op": "eq", "value": "ZT"},
    {"field": "t-1.is_one_word", "op": "eq", "value": false},
    {"field": "t-2.amplitude", "op": "gte", "value": 8.0},
    {"field": "t-1.open_ret", "op": "gte", "value": 8.0}
  ]
}
```

`entry_json`：

```json
{
  "field": "entry_gap",
  "op": "between",
  "min": 0.01,
  "max": 2.0,
  "inclusive": true
}
```

### 4. 规则统计表 `t0_reference_rule_stats`

统计表保存某个规则在某个数据批次和统计期间的结果。

建议字段：

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `rule_id` | 规则 ID |
| `batch_id` | 数据批次 |
| `period_key` | `all` 或具体年份/期间 |
| `date_start` | 样本开始日期 |
| `date_end` | 样本结束日期 |
| `sample_count` | 样本数 |
| `profit_win_rate` | T0 收盘价高于竞价买入价的比例 |
| `target_rate` | T0 日内收益大于等于 2.5% 的比例 |
| `loss_rate` | T0 日内收益小于 0 的比例 |
| `avg_pnl` | 平均日内收益 |
| `median_pnl` | 日内收益中位数 |
| `research_tier` | `A`、`B`、`normal` 或 `insufficient` |
| `updated_at` | 更新时间 |

建议唯一约束：`(rule_id, batch_id, period_key)`。

其中：

```text
严格胜率 = count(T0收盘价 > T0竞价买入价) / 样本数
日内收益 = (T0收盘价 - T0竞价买入价) / T0竞价买入价 * 100
达标率 = count(日内收益 >= 2.5%) / 样本数
真亏率 = count(日内收益 < 0) / 样本数
```

严格胜率是新统一库的主胜率；旧库中的 `WinRate` 仍表示历史的 2.5% 达标率，不能直接改名覆盖。统计表需要建立 `(rule_id, batch_id, period_key)` 唯一索引，并建立 `(rule_id, period_key)` 查询索引。

### 5. 旧逻辑适配

现有 `t0_pattern_stats` 继续存在，并由旧适配器提供：

- 普通 `pattern` 查找仍按 `(pattern, window)`；
- 旧 `PatternT0N`、`PatternWinPct`、`PatternFailPct` 字段继续保持原语义；
- 旧归档 JSON 不要求立即重写；
- 新规则没有普通标签序列时，不强行写入旧 `Pattern` 字段。

当前普通形态统计可以逐步导入通用规则表，但导入不能替代旧表，直到前端和历史归档验证完成。新旧两套统计批次必须分别记录来源和日期范围。

旧库无法从 `WinRate` 和 `FailRate` 反推出严格胜率，因此旧形态迁移到通用库时必须基于 Gob 回填原始观察后重新聚合。回填完成前，旧形态继续走旧适配器；新通用库不可用时，接口回退到旧适配器。

## 匹配与统计接口

规则引擎对外只提供少量接口，隐藏规则 JSON 解析、字段读取、派生指标计算和统计聚合细节：

```text
BuildReferenceObservation(dailyBars, tradeDate, entry) -> observation
MatchReferenceRules(preT0View, entryView, enabledRules) -> ruleHits
AggregateReferenceStats(observations, rules, batch) -> stats
EnrichT0Result(result, observation) -> result
```

约束：

1. `BuildReferenceObservation` 必须能从 Gob 重建同一条观察数据；
2. `MatchReferenceRules` 只能读取 T-3、T-2、T-1 和 T0 竞价字段；匹配器不能接收 T0 收盘、最高、最低等结果字段；
3. T0 收盘价只能进入统计结果，不能参与规则匹配；
4. 规则匹配器不得依赖 Flutter 或 GORM，便于离线回测和单元测试；
5. 所有日期按交易日排序，不能用自然日索引代替真实的 T-3、T-2、T-1。

## 数据更新与回填

### 全量回填

使用本地日线 Gob 按日期、股票构建原始观察。回填顺序为：

1. 读取当日 Gob 的股票池快照并记录 `universe_batch`；
2. 检查 T0 和前三根历史日线是否完整；
3. 从源 Gob/缓存版本确定性生成不可变 `source_batch` 和 `source_hash`；同一份未变化的源数据重复回填必须得到相同值；
4. 写入新的 `t0_reference_observations` 版本，不覆盖旧版本；
5. 将旧版本标记为非活动版本，并将新版本标记为活动版本；
6. 写入或更新三个 `t0_reference_bars`；
7. 记录来源批次和日期范围；
8. 对启用规则重新聚合统计；
9. 更新研究等级。

回填必须幂等，重复执行同一日期不会产生重复观察或重复统计。

### 增量更新

每日 T0 日线缓存完成后，只新增当天观察并重新计算受影响规则。历史观察原则上不覆盖；如发现源 Gob 修复，必须使用新的 `source_batch` 和 `source_hash` 重建对应日期，将旧版本保留为非活动版本，并保留可追溯批次。

## 错误与安全

- 缺少任意一根 T-3～T-1 K 线时，不生成完整观察，不参与规则统计。
- 缺少 T0 开盘价时不能计算竞价涨幅，保留数据状态但不参与 T0 交易统计。
- 缺少实际 `entry_price` 时，观察只能标记为 `incomplete`，不能使用 `t0_open` 静默替代实时竞价价。
- T0 开盘价小于等于 0 时拒绝计算收益率。
- 规则 JSON 解析失败、字段不存在或运算符不支持时，该规则标记为无效，不影响其他规则。
- 统计写入使用事务，避免规则定义已更新但统计只写入一半。
- 规则只允许访问白名单字段，禁止执行动态 SQL、Go 表达式或外部脚本。
- 原始观察表和 K 线表只保存必要的行情数据，不向 Flutter 下发完整历史 K 线。
- Gob 缺失不会静默使用未来行情补齐；必须返回数据不完整状态并记录日期、股票和来源。
- 数据库需要为观察表建立 `trade_date`、`stock_code + trade_date` 索引，为 K 线表建立 `observation_id + offset` 索引。

## 验收标准

### 兼容性

1. 旧 `t0_pattern_stats` 可以继续同步和查询。
2. 旧归档 JSON 仍能展示原有形态、买入信号和颜色。
3. 普通形态的旧 `WinRate` 仍表示 2.5% 达标率。
4. 新规则没有普通形态标签时，不破坏旧字段。

### 原始数据完整性

1. 同一 `(trade_date, stock_code, source_batch)` 只能有一条原始观察，同一股票日最多一个活动版本。
2. 每条完整观察必须有 T-3、T-2、T-1 三根 K 线。
3. T-3～T-1 使用交易日偏移，不使用自然日推算。
4. T0 日线开盘价、实际竞价买入价、收盘和两种涨幅可以从保存的数据重新计算。
5. 源 Gob 修复后旧版本仍可追溯，新版本可以被标记为活动版本。
6. 全量回填重复执行结果一致。

### 规则扩展

1. `YX|ZT|ZT` 可以作为普通序列规则入库。
2. “T-2 振幅≥8% + T-1 开盘涨幅≥8%”可以作为条件规则入库。
3. 新增条件不需要新增数据库字段。
4. 条件顺序变化但语义相同的规则会被规范化去重。
5. 新规则只读取 T-3～T-1 和 T0 竞价字段，不发生 T0 收盘价前视。

### 统计与优先级

1. 严格胜率、2.5% 达标率和真亏率分别正确计算。
2. 样本数小于 20 的 65% 规则不能标记为 A 级。
3. 样本数 10～19 且严格胜率达到 65% 的规则最多标记为 B 级。
4. 规则优先级可以参与列表排序，但不会自动改变红色/深红色逻辑。
5. 统计结果能够按全区间和年度区间查询，便于识别样本过拟合。

### 兼容切换

1. 新通用库不可用时，旧形态字段仍按旧逻辑返回。
2. 新规则统计失败时，不阻塞主板 T0 选股。
3. 新旧统计批次、日期范围和来源可以追溯。
4. 完成历史回填后，可以只依赖本地数据重跑规则分析，不要求重新抓取行情。
5. 当前样本的股票池来源、数据批次和覆盖范围可以在统计结果中追溯。
