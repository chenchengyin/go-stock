# 红策历史分时与交易日修复

> 实施方式：当前会话直接实施，测试通过后提交并部署阿里云。

**Goal:** 历史分时使用同花顺 single_trend，并正确处理跨假期的 T+1、前后交易日和昨收。

**Architecture:** 保留现有分时 API 与前端数据格式。single_trend 使用 YYYYMMDD，校验股票、市场及每个时间戳；将累计成交量/额转为分钟增量，并携带 base_price。交易日使用共享日线日期与缓存中的当天日线事实，不以缓存文件存在作为依据。

**Tech Stack:** Go、httptest、Flutter 现有分时组件。

**Spec:** 本会话用户要求：改用正确分时接口，一起修复交易日和昨收，测试通过后提交并部署阿里云。

## Global Constraints

- 只提交本次修复；保留工作区其他改动。
- 数据源不得串日期、串股票；空数据不当成功缓存。
- 保留备用源、进程级两槽限流和有限重试。
- 部署前备份线上二进制；不替换前端或历史选股数据。

## Review Focus

- 返回错误日期/代码/市场、无效价格、重复或乱序分钟：不能冒用。
- 成交量/额为累计值：均价不能再次重复累计。
- 假期存在日线缓存文件，但没有当天日线：仍必须跳过。
- 实际分钟已返回 base_price：不得因日线网络失败阻塞绘图。
- 旧缓存缺少或带错昨收：不能掩盖修复。
