# 后台管理—用户管理一期设计

## 背景与目标

现有 Go 服务已经有普通用户账号、会话和 `status` 字段，但没有管理员入口。第一期增加一个轻量后台管理页面，让管理员可以登录后查看账号，并控制普通用户是否可以继续登录。

管理员账号按当前约定固定为 `admin` / `admin`。页面复用项目现有 Vue 3 + Naive UI 风格，挂在现有前端的 `/admin` 路由下。

## 非目标

- 不做角色树、权限配置或多管理员账号。
- 不做用户删除、密码重置、批量导入导出或统计看板。
- 不改变普通用户注册、登录、单设备会话和用户数据隔离逻辑。
- 不把管理员账号写入普通 `users` 表，也不新增独立后台数据库。

## 权限

- `POST /api/admin/login` 公开，仅接受用户名 `admin` 和密码 `admin`。
- `/api/admin/users` 及其子路径必须携带管理员登录返回的 Token。
- 普通用户 Bearer Token、缺失 Token 或过期的管理员 Token 均不能访问后台接口。
- 管理员只能管理普通用户记录；一期不提供提升用户为管理员的操作。

## 页面 / 接口（用户可观察行为）

### 后台页面

进入 `/admin`：

1. 未登录时展示管理员登录表单，账号和密码输入框默认填入 `admin`，提交后进入用户管理内容。
2. 登录后展示用户管理表格，列出账号、昵称、角色、状态、注册时间和操作。
3. 顶部提供账号/昵称关键词搜索、查询和刷新。
4. 对启用用户显示“禁用”，对禁用用户显示“启用”；变更前弹出确认，成功后刷新列表并提示结果。
5. Token 失效时清理本地管理员登录态并回到登录表单；接口错误显示后端返回的中文提示。

### 管理员接口

`POST /api/admin/login`

请求：

```json
{"username":"admin","password":"admin"}
```

成功返回 `200`：

```json
{"accessToken":"<opaque-token>","expiresAt":"<RFC3339>"}
```

`GET /api/admin/users?keyword=<账号或昵称>`

成功返回 `200`：

```json
{
  "items": [
    {
      "id": "<id>",
      "phone": "13800000000",
      "nickname": "用户",
      "role": "user",
      "status": "active",
      "createdAt": "<RFC3339>",
      "updatedAt": "<RFC3339>"
    }
  ],
  "total": 1
}
```

`PATCH /api/admin/users/{id}/status`

请求：

```json
{"status":"active"}
```

`status` 只允许 `active` 或 `disabled`。禁用用户时同时撤销该用户的有效会话，使其已有客户端立即失效；重新启用后可以再次登录。

## 架构与数据

后端在 `backend/flutter_api` 增加独立的 `AdminService` 和管理员 HTTP handler：

- 登录只在服务端比较固定凭据，生成随机不透明 Token，服务端内存中仅保存 Token 哈希和过期时间；服务重启后管理员需要重新登录。
- 普通用户表继续使用现有 `users`，后台返回列表时只映射安全字段，不返回 `PasswordHash`、会话 Token 或设备信息。
- 用户列表通过 `keyword` 对 `phone` 和 `nickname` 做包含匹配，按 `created_at DESC` 返回全部结果；一期不增加分页参数。
- 状态变更只允许更新目标用户的 `status`，并复用现有会话撤销逻辑。
- 在现有 `newHTTPHandler` 中挂载 `/api/admin/*`，管理员接口先经过管理员 Token 校验；普通认证中间件不拦截管理员登录接口。

前端在现有 `frontend/src/router/router.js` 增加 `/admin` 路由，在 `frontend/src/components/admin.vue` 实现登录态、请求和表格；`frontend/src/App.vue` 增加“后台管理”入口。请求地址沿用当前本地服务 `http://localhost:8080`。

## 错误与安全

- 固定凭据错误返回 `401`，错误信息统一为“管理员账号或密码错误”。
- 缺失、伪造或过期管理员 Token 返回 `401`，不泄露 Token 是否存在。
- 用户不存在返回 `404`；状态值非法返回 `400`。
- 登录 Token 不写日志、不写数据库、不放入 URL；页面只保存在浏览器 `localStorage`。
- `admin/admin` 是一期约定的初始凭据，仅适用于当前内网/本地部署场景；后续如对外部署需改为可配置凭据。

## 验收标准

1. 启动服务后，打开 `/admin` 可以看到管理员登录页。
2. 使用 `admin/admin` 登录成功，错误凭据不能进入用户管理页。
3. 用户管理页可以列出已有普通用户，并按账号或昵称搜索。
4. 管理员可以启用/禁用用户；禁用后该用户不能登录，已有会话也失效；启用后恢复登录。
5. 普通用户 Token 和未登录请求不能访问管理员接口。
6. 现有普通用户登录、注册、单设备会话和业务接口行为保持不变。
