# 主板 T0：近 7 日涨停记忆纳入涨停破板

## 背景

盘达主板策略过滤 2「近 7 日有涨停」目前只认 **收盘涨幅 ≥ 9.8%**。日内摸到涨停但没收住的「涨停破板」通常收盘不到 9.8%，进不了股池；结果卡片上的「涨停破板」标记也就打不上（标记只给已经入选的票）。

前日标记里破板口径已经存在：最高涨幅 ≥ 9.85% 且收盘涨幅 < 9.85%。需要把同一类日子并进过滤 2，而不是另开一条选股链。

## 目标

1. 近 7 个交易日里，**收盘涨停或涨停破板** 任一命中，即过过滤 2。
2. `涨停日期` 与过滤 2 使用同一套判定；破板日与封板日混排，不加「破板」后缀。
3. 抽出共用纯函数，避免过滤与两处组装各写一套阈值。
4. 收盘涨停门槛从 9.8% 改为 **≥ 9.89%**；破板仍用现有标记的 9.85%。

## 非目标

- 不改市值、成交额、开盘涨幅、MA20 暂缓状态。
- 不改 `pickPrevDayTag`（破板红标、破板且跌停清空标记等展示规则保持 9.85% / -9.9%）。
- 不回填已有 `t0_selection_*.json`；新规则从下次预热 / 选股生效。
- 不改 Flutter 卡片结构（继续读 `涨停日期`、`标记`）。
- 不改 Python 脚本 `T0开盘日线选股.py`。
- 不新增网络请求、不扫全历史日线、不为破板再扫一遍全市场。

## 决策摘要

| 项 | 选择 |
|----|------|
| 实现结构 | 抽出「这一天算不算涨停记忆」纯函数，过滤 2 与两处 `涨停日期` 共用（方案 1） |
| 窗口 | 内存取 `hist` 末尾最多 8 根（7 个交易日 + 最早那天的前收）；不额外拉 K 线 |
| 收盘涨停 | 收盘涨幅 ≥ 9.89% |
| 涨停破板（入选） | 最高涨幅 ≥ 9.85% 且 收盘涨幅 < 9.85% |
| 破板后收跌停 | 该日仍计入涨停记忆 |
| 夹缝 | 9.85% ≤ 收盘涨幅 < 9.89% 且不满足破板 → 该日两边都不算 |
| `涨停日期` | 命中日混排、无后缀；时间升序后取最近 3 个；没有则 `-` |
| 前日标记 | 不改 |
| 旧归档 | 不回填 |
| 性能 | 仍是股票数 × 近 7 日内存扫描；过滤阶段只做布尔判断，不拼日期字符串 |

## 1. 选股链（改完后的完整逻辑）

数据口径不变：主板 `60`/`00`；流通市值优先、否则总市值，50～9000 亿。日线来自现有 gob / 预热；`histBarsBeforeTradeDate` 去掉选股当日 K。涨停记忆、成交额、标记都只看昨天及更早。

过滤按顺序 **且**：

1. 主板 + 市值（不变）
2. 近 7 日涨停记忆（本节）
3. 前一交易日成交额 ≥ 5 亿（不变）
4. 收盘 > MA20（仍暂缓，不挡人）
5. T0 竞价开盘涨幅 0.01%～3%（不变；预热 / 候选阶段没有这一步）

## 2. 涨停记忆判定

### 窗口

对已剔除选股当日 K 的 `hist`：

- 取末尾最多 8 根，得到最多 7 段日收益。
- 这第 8 根是最早候选日的前收，已在现有日线缓存里，**不是新的 HTTP / K 线请求**。
- 不足 8 根：有几段算几段；一段都算不了则不过滤 2。

相对当前实现：过滤 2 原先切最后 7 根、只算出 6 段收益；组装 `涨停日期` 已按 8 根 / 7 段。本次过滤与组装对齐为 7 段。多 1 次浮点比较，可忽略。

### 单日公式

某日相对前收 `P`。`P == 0` 则跳过该日。

```text
closeRet = (收盘 - P) / P × 100
highRet  = (最高 - P) / P × 100
```

最高价缺失或为 0：最高涨幅视为 0，不可能破板；仍只看收盘是否 ≥ 9.89%。

**该日算涨停记忆**（满足任一即可）：

| 类型 | 条件 |
|------|------|
| 收盘涨停 | `closeRet ≥ 9.89` |
| 涨停破板 | `highRet ≥ 9.85` 且 `closeRet < 9.85` |

冲涨停后收跌停：最高仍 ≥ 9.85，该日算记忆。

夹缝（按产品选择保留）：`9.85 ≤ closeRet < 9.89` 时不满足破板（破板要求收盘 < 9.85），也不满足新的收盘涨停 → 该日不计入。

### 过滤 2

近 7 日里有一天算涨停记忆 → 通过。只返回是否入选，过滤阶段不拼接 `涨停日期`、不建额外大 map。

所有现有 `filterLimitUpRecent` 调用点都走同一套判定（预热候选统计、`buildT0CandidateList`、`RunT0Selection` 等）。保留函数名与签名，内部改为调用纯函数；调用处收盘门槛改为 9.89，破板门槛在纯函数内固定 9.85。不新增全市场扫描。

### `涨停日期`

与过滤 2 同一判定。命中日按时间升序，与现网一致取最后 3 个（最近的），逗号拼接；一个都没有则为 `-`。破板日与封板日同一列表、不加后缀。昨日是否破板仍靠 `标记` 字段的「涨停破板」红标区分。

两处组装（`assembleT0CandidateResults`、`RunT0Selection` 结果循环）都改为调用共用函数，禁止再手写 `ret >= 9.8`。

### 前日标记

`pickPrevDayTag` 不改：破板仍是最高 ≥ 9.85 且收盘 < 9.85；破板且跌停时 `标记=""`，股票若已入选则留在列表中。入选门闸变宽后，更多昨日破板票会进池并带上红标。

## 3. 性能红线

现在已经是「股票数 × 近 7 日」内存扫描。新逻辑只多几次浮点比较和一次纯函数调用，复杂度不变。

禁止：

- 额外 HTTP / K 线 / 腾讯请求
- 对单只股票扫描全历史日线
- 过滤阶段拼日期字符串或为破板再扫一遍全市场

## 4. 异常

- 不因标记或破板单独失败、不重拉行情。
- 某日前收为 0：跳过该日。
- K 线过短：能算则算，不能算则该股不过滤 2。

## 5. 测试

单测，不打真实网络。

1. 近 7 日只有破板、没收盘涨停 → 过过滤 2，`涨停日期` 含那天。
2. 只有收盘 ≥ 9.89 → 过过滤 2。
3. 收盘 9.86（夹缝）且不满足破板 → 不因这一天过过滤 2。
4. 冲涨停后收跌停 → 该日算记忆。
5. 过滤与 `涨停日期` 对同一组 `hist` 判定一致。
6. 现有 `TestPickPrevDayTag` 保持 9.85 口径，本需求不改。

## 6. 实现顺序建议

1. 纯函数：单日是否涨停记忆 + 近 7 日是否命中 + 近 7 日命中日期列表。
2. 单测覆盖第 5 节用例。
3. `filterLimitUpRecent` 与两处 `涨停日期` 改为调用纯函数；注释 / 文件头过滤链说明改为 9.89 + 破板。
4. 用现有日线缓存对某一历史日跑一遍候选，抽检「昨日破板但近 7 日无收盘涨停」的票是否出现。
