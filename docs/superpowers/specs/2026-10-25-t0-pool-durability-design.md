# T0 股票池历史恢复与防丢失

目标：恢复有可信来源的日期，盘点所有历史日期，防止单个共享日线文件或服务未启动导致股票池继续丢失。用户已要求直接修复。

证据：678 个共享日线交易日，9 个日期有有效的完整当天股票池，669 个缺失；旧缓存多数没有 schema/完整性标记。5 个本机 LFS 大快照均没有 2026-10-20。云端 SSH 认证失败，已询问可用连接或备份路径，继续完成独立工作。

采用方案：每个日期单独原子保存股票池 JSON（日期、来源、捕获时间、完整标记、股票明细），保留冲突检测。加载共享 GOB 时从独立池恢复缺失的 dated pool；不使用当前 Stocks 推断历史池。实时池一旦完整获取立即落盘，早于日线下载；每日定时任务在日线刷新前先留存池，日线下载失败不影响池存续。已有共享池和 schema=2 完整缓存可按其真实来源恢复。

历史下拉仅包含具有完整池或已确认正式名单的日期；当天仍保留等待/预热入口。审计报告包含全部原始日线日期及缺失原因，直接请求缺失日仍明确失败。669 个未核验历史日不能伪造为已恢复。

现有 ensure 启动脚本由 launchd 每五分钟检查，并在登录加载时检查；服务已运行立即退出。保留现有工作日 08:00 调用，不另开高频轮询服务。电脑关机或整天睡眠仍不能保证采集，需依赖持续在线服务器。

替代方案：只修 UI 无法防丢；用邻近日期/当前池回填会制造历史偏差，拒绝采用。新增收费数据源需要可验证来源和既有权限，本次不猜测历史流通市值。
