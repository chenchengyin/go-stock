# 模块权限管理与独立后台设计规格

## 1. 背景与目标

当前 Flutter 用户端的「盘达」页面包含多个内部 Tab。后台目前嵌在 Wails Vue 客户端中，只提供管理员登录、用户查询和启停，无法配置用户可以查看哪些业务模块。

本次设计引入直接面向用户的模块白名单权限：管理员在独立公网网页中选择一个或多个用户，再勾选模块；用户端登录后获取自己的模块清单，只展示清单中的入口。权限判断必须同时存在于客户端展示层和服务端业务接口层，不能只通过隐藏 Tab 实现。

首期只实现「盘达」内部 Tab 的权限配置，但模块协议、目录字段和用户端壳层接口要兼容未来的底部导航和其他页面。

## 2. 已确认的产品决策

| 项目 | 决策 |
| --- | --- |
| 首期范围 | 只配置 Flutter 用户端「盘达」内部 Tab |
| 当前 Tab | 监控股票（自选）、紫策、主板策略、蓝策、自选异动、全市场 |
| 公开模块 | 监控股票（自选）、自选异动、全市场，对所有已登录用户可见 |
| 受控模块 | 紫策、主板策略、蓝策，以及未来新增的其他业务模块 |
| 受控默认值 | 默认不可见，必须由管理员按用户授权 |
| 授权对象 | 具体用户，不使用用户组作为首期授权对象 |
| 批量操作 | 可选中多个用户后一次性配置模块权限 |
| 权限关系 | 每个模块独立；授权或撤销一个模块不影响其他模块 |
| 客户端入口 | 服务端返回哪些模块，用户端就显示哪些对应入口 |
| 无权限体验 | 隐藏入口；直接访问或请求业务接口时返回无权限 |
| 生效时机 | 服务端保存后立即生效；客户端登录恢复、回前台或手动刷新时重新获取 |
| 后台形态 | 独立网页，不嵌入 Wails 客户端 |
| 后台监听 | 独立、可配置的非标准端口，建议默认 `:18080` |
| HTTPS | 本期不实现；公网正式使用前必须补充 HTTPS 或反向代理 |
| 管理员账号 | 使用数据库账号和 `admin` 角色，不再使用写死的 `admin/admin` |

## 3. 总体方案

采用“代码注册模块目录 + 数据库存储用户授权”的方案：

```text
模块定义（后端注册）
        |
        +--> 后台读取全部模块并配置用户授权
        |
        +--> 用户请求 /api/auth/modules
                    |
                    v
             当前用户可见模块清单
                    |
                    v
        Flutter 根据模块编码动态构建入口和 Tab
```

模块目录不是让管理员凭空创建页面。一个模块必须先在后端登记，并在客户端存在对应页面/组件，才会出现在后台配置列表中。未来增加模块时，由开发者同时增加页面、业务接口权限和模块定义；新模块默认使用用户白名单策略，不自动开放。

权限清单和业务数据是两层不同的契约：`/api/auth/modules` 只返回模块元数据，不返回股票结果。业务接口可复用底层计算和缓存，但每个受控 Tab 的接口入口必须独立校验对应模块编码。

## 4. 模块目录

模块使用稳定编码进行权限判断，不使用中文名称、Tab 下标或页面标题。

### 4.1 首期目录

| 编码 | 名称 | 位置 | 权限策略 | 排序 |
| --- | --- | --- | --- | ---: |
| `radar.monitored` | 监控股票（自选） | `radar_tab` | `public` | 10 |
| `radar.purple_strategy` | 紫策 | `radar_tab` | `user_allowlist` | 20 |
| `radar.main_strategy` | 主板策略 | `radar_tab` | `user_allowlist` | 30 |
| `radar.blue_strategy` | 蓝策 | `radar_tab` | `user_allowlist` | 40 |
| `radar.watch_changes` | 自选异动 | `radar_tab` | `public` | 50 |
| `radar.all_changes` | 全市场 | `radar_tab` | `public` | 60 |

### 4.2 定义字段

后端模块定义至少包含：

```text
code          稳定唯一编码
name          展示名称
client        flutter_web、flutter_mobile 等客户端标识
placement     radar_tab、bottom_nav、page 等入口位置
parent_code   父模块编码，可为空
sort          同级入口排序
access_mode   public 或 user_allowlist
```

首期模块目录由 Go 代码注册，后台只读取和展示，不提供任意创建功能。客户端维护同编码到页面构建器的本地映射，并使用服务端清单过滤本地定义；服务端不能下发任意路由或组件名称来驱动客户端执行代码。

## 5. 数据模型

### 5.1 用户授权表

新增 `module_user_grants` 表：

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `module_code` | 模块编码 |
| `user_id` | `users.id` |
| `created_by` | 执行授权的管理员用户 ID |
| `created_at` | 授权时间 |
| `updated_at` | 更新时间 |

建立 `(module_code, user_id)` 唯一索引，并为 `user_id` 建索引。插入授权前必须校验模块存在且为 `user_allowlist`，以及用户存在；公开模块不产生授权记录。

首期不增加拒绝记录。受控模块“无记录即拒绝”，因此取消授权只需删除对应记录。未来若需要用户组或角色授权，可新增其他授权来源表，不改变用户端模块清单格式。

### 5.2 管理员会话

现有管理员服务中的硬编码账号和进程内 Token 表替换为数据库管理员账号和独立 `admin_sessions` 表。管理员会话与普通用户的 `user_sessions` 分离，避免管理员在浏览器登录时撤销同一账号的普通客户端会话。

`admin_sessions` 至少包含：`id`、`user_id`、`token_hash`、`created_at`、`last_seen_at`、`expires_at`、`revoked_at`。浏览器使用 `HttpOnly` Cookie 保存会话，后台网页脚本不能直接读取 Token；启用 HTTPS 后设置 `Secure` 属性。

管理员账号仍使用 `users` 表中的 bcrypt 密码哈希，只有 `role=admin` 且状态有效的账号可以进入后台。首次部署通过 `admin-init` 命令创建管理员：命令接收账号和昵称参数，并从交互式隐藏输入读取密码；如果该账号已存在，命令必须明确失败，不得覆盖现有密码。命令每次只创建一个新管理员，可以重复运行以创建多个管理员。密码只写入 bcrypt 哈希，初始化过程不得把密码写入日志，也不得保留 `admin/admin` 回退逻辑。

## 6. 服务端接口

### 6.1 用户端权限清单

```text
GET /api/auth/modules
```

接口要求普通用户已认证，返回当前用户可见模块，按 `sort` 排序：

```json
{
  "version": 1,
  "modules": [
    {
      "code": "radar.main_strategy",
      "name": "主板策略",
      "client": "flutter_web",
      "placement": "radar_tab",
      "parentCode": "radar",
      "sort": 30
    }
  ]
}
```

公开模块始终包含在结果中。受控模块只有用户存在对应授权记录时才返回。这个响应只表达“有哪些入口可以显示”，不承载 T0、异动或其他业务数据。

### 6.2 后台管理接口

后台接口只在独立管理服务上提供，并要求管理员会话：

```text
POST /api/admin/login
POST /api/admin/logout
GET  /api/admin/me
GET  /api/admin/users?keyword=...
GET  /api/admin/modules
GET  /api/admin/access?user_ids=user-a,user-b
GET  /api/admin/modules/{module_code}/users
PUT  /api/admin/access
```

批量保存请求：

```json
{
  "userIds": ["user-a", "user-b"],
  "moduleCodes": [
    "radar.main_strategy",
    "radar.purple_strategy"
  ]
}
```

保存语义是：对选中的用户，完整覆盖受控模块授权集合。`moduleCodes` 为空表示撤销这些用户的全部受控模块权限。公开模块不能被修改；请求中包含公开模块时返回参数错误，而不是创建无意义的授权记录。用户和模块校验、删除旧授权、插入新授权在同一个事务内完成，失败时全部回滚。

多用户编辑时，查询接口返回每个用户当前的受控模块集合；网页根据集合计算已勾选、未勾选和半选状态。禁用用户可以保留授权，禁用期间不能登录，重新启用后授权自动恢复。

### 6.3 业务接口保护

业务接口在认证通过后，还必须调用模块权限服务校验具体模块编码。未授权返回：

```json
{
  "code": "MODULE_FORBIDDEN",
  "message": "暂无该功能访问权限"
}
```

HTTP 状态为 `403`。权限清单只决定入口展示；服务端业务接口是最终安全边界。当前紫策、主板策略、蓝策可以共享 T0 计算、行情合并和缓存，但接口权限判断必须按三个模块分别处理，授权一个模块不得自动放行其他模块。

## 7. 独立后台网页

### 7.1 项目与运行方式

新增独立 `admin-web/` Vue 项目，不引用 Wails 运行时、不依赖 `frontend/dist`，开发时单独运行 Vite，生产构建后由 Go 管理服务提供静态文件和 SPA 回退。

管理服务读取 `GO_STOCK_ADMIN_ADDR`，建议默认监听 `:18080`。同一端口提供管理网页和 `/api/admin/*`，网页与 API 同源，首期不需要开放跨域。8080 保留给 Flutter 用户端 API/Web，不再注册 `/api/admin/*`。

后台网页入口为：

```text
http://服务器地址:18080/
```

实际部署可以通过环境变量换成其他非标准端口。非标准端口只降低普通扫描命中率，不承担权限和身份安全职责。

### 7.2 用户管理页面

保留现有用户管理能力并扩展：

- 按账号、昵称搜索；
- 查看角色、状态、注册时间；
- 启用/禁用普通用户；
- 多选用户；
- 点击“配置模块权限”；
- 在弹窗中勾选受控模块；
- 完成后批量保存。

### 7.3 功能管理页面

功能管理展示模块目录，包括：

- 模块名称和编码；
- 所属客户端和位置；
- 公开或用户授权策略；
- 已授权用户数量；
- 受控模块的授权用户查看入口。

公开模块显示为“公开模块”并锁定，不提供复选修改。受控模块显示为“用户授权模块”。首期以用户管理中的批量配置为主要编辑入口，功能管理提供模块总览和反向查看授权用户。

### 7.4 Wails 边界

移除 Wails Vue 中的后台入口、`/admin` 路由和嵌入式后台页面。Wails 客户端仍可继续启动 8080 用户端服务，但用户访问后台必须通过独立浏览器网页。

## 8. Flutter 用户端

### 8.1 权限加载

在认证完成后增加模块权限仓库和状态管理。登录成功、恢复登录、应用回到前台和手动刷新时调用 `/api/auth/modules`。

首次加载权限前，受控模块不展示；基础模块可以作为安全回退。权限请求失败时隐藏受控模块并显示重试提示，不因为模块权限失败而强制退出普通登录态。

### 8.2 盘达动态 Tab

Flutter 为每个当前 Tab 定义稳定模块编码和页面构建器：

```text
模块编码 → 标题 → Tab 内容 → 数据加载器
```

`RadarPage` 根据权限清单过滤模块定义，再生成 `TabBar` 和 `TabBarView`。TabController 的长度、当前索引、懒加载状态和刷新逻辑都基于模块编码，而不是固定的 6 个下标。当前 Tab 被撤权时，停止该模块的刷新任务并切换到第一个可见模块。

用户只有主板策略权限时，盘达显示：

```text
监控股票（自选） | 主板策略 | 自选异动 | 全市场
```

用户同时拥有主板策略、紫策、蓝策时，六个 Tab 全部显示。取消其中任意一个，只隐藏对应 Tab。

### 8.3 未来底部导航

首期不改 `AppShell` 的底部导航行为，但模块定义已包含 `placement=bottom_nav` 和父模块字段。未来接入超短情绪、市场快讯或其他页面时，复用同一套权限状态和模块清单，不重新设计鉴权协议。

## 9. 生效、错误与安全边界

| 场景 | 行为 |
| --- | --- |
| 未认证访问权限清单 | `401 UNAUTHENTICATED` |
| 用户没有受控模块授权 | 权限清单不返回该模块 |
| 直接请求受控业务接口 | `403 MODULE_FORBIDDEN` |
| 管理员登录失败 | 统一返回无效凭据，不暴露账号是否存在 |
| 普通用户访问后台 | `401/403`，不返回后台数据 |
| 权限批量保存部分失败 | 事务回滚，不产生部分结果 |
| 权限请求临时失败 | 隐藏受控模块，基础模块保留并允许重试 |
| 页面打开后被撤权 | 下次业务请求收到 403，移除当前模块并回退 |
| 普通用户被禁用 | 登录和既有会话失效，模块授权记录保留 |
| 授权模块不存在 | 后台拒绝请求并返回参数错误 |

管理员登录、授权和状态变更日志不得记录密码、明文 Token 或敏感请求头。公网部署虽然暂不实现 HTTPS，但发布说明必须明确：非标准端口不是安全措施，正式公网运行前需要 HTTPS、反向代理、防火墙或其他等价的传输和访问保护。

## 10. 迁移与兼容策略

1. 在认证迁移入口中创建 `module_user_grants` 和 `admin_sessions`，迁移必须幂等。
2. 注册当前六个模块定义，三项基础模块使用 `public`，三项策略模块使用 `user_allowlist`。
3. 现有普通用户不插入策略模块授权，因此升级后仍能使用三项基础模块，但不会自动获得紫策、主板策略或蓝策。
4. 现有 Wails 后台页面和菜单移除；独立 `admin-web` 作为新的后台入口。
5. 8080 用户端接口继续使用普通用户认证；管理 API 仅在独立端口注册。
6. 不修改现有 T0 选股规则、策略排序、缓存格式或归档文件；只在接口入口增加模块权限边界。

## 11. 测试设计

### 11.1 Go 后端

- 模块目录包含当前六个模块，编码唯一、排序正确、公开/受控策略正确；
- 公开模块对任何有效用户返回；
- 受控模块无授权时不返回；
- 主板策略、紫策、蓝策授权互不影响；
- 多用户批量保存准确覆盖受控模块集合；
- 空模块集合可以撤销全部受控权限；
- 重复授权幂等，唯一索引生效；
- 不存在用户、模块或公开模块写入被拒绝；
- 普通用户不能访问管理员接口；
- 数据库管理员可以登录，普通用户不能登录后台；
- `admin-init` 能创建首个及后续管理员，重复使用已有账号时不会覆盖现有密码；
- 管理员会话过期、撤销和服务重启后的行为正确；
- 未授权业务接口返回 `403 MODULE_FORBIDDEN`；
- T0 业务共享缓存时仍按请求模块独立鉴权，不因授权一个策略 Tab 放行其他策略 Tab；
- 禁用用户无法登录，但重新启用后历史授权保留。

### 11.2 Flutter

- 权限清单解析正确；
- 只返回三个基础模块时，盘达只显示三个基础 Tab；
- 分别覆盖只授权紫策、只授权主板策略、只授权蓝策，以及任意多选组合；
- 六个模块全部可见时顺序与模块目录一致；
- 隐藏中间 Tab 后 TabController、滑动、懒加载和刷新不依赖旧下标；
- 权限刷新撤销当前 Tab 后能回退到可见 Tab；
- 权限请求失败时受控 Tab 隐藏，基础 Tab 可用；
- 未来 `bottom_nav` 模块能复用权限状态，不改变权限接口格式。

### 11.3 独立后台网页

- 登录、退出和过期会话跳转正常；
- 用户搜索和状态启停保持可用；
- 多选用户后能打开模块权限弹窗；
- 模块复选框支持全选、未选和半选状态；
- 保存后重新查询，多个用户权限一致；
- 取消一个策略模块不改变其他策略模块；
- 公开模块显示锁定状态且不可修改；
- 功能管理中的授权人数与用户管理配置结果一致；
- 管理网页可以在独立端口直接访问，不依赖 Wails。

## 12. 首期实现边界

本设计对应的首期实现包含：

- Go 模块目录、权限服务、授权表和管理员会话；
- 一次性管理员初始化命令；
- 独立管理端口与 `admin-web` 网页；
- 功能管理、用户管理和多用户批量模块授权；
- Flutter 权限清单加载和「盘达」六 Tab 动态展示；
- 受控业务接口的服务端权限校验；
- 相关 Go、Flutter 和管理网页测试。

本期不包含：

- 用户组、角色继承或复杂 RBAC；
- 任意创建客户端不存在的动态页面；
- 管理员操作审计报表；
- HTTPS 证书、反向代理和公网防火墙配置；
- Wails 其他业务页面的实际权限接入；
- T0 策略规则、排序、缓存和业务结果格式改造。
