# 主板策略：前日标记 + 收盘后刷新归档收盘涨幅

## 背景

盘达「主板策略」结果已归档到 `backend/data/cache/t0/selection/t0_selection_{date}.json`。现状：

- 列表项缺少对「前一交易日」强弱结构的一眼标记（破板 / 跌停 / 大阴线）。
- `T0收盘涨幅(%)` 多为当日首次正式选股时的盘中快照；默认归档不覆盖，收盘后不会自动变成真收盘涨幅。
- 直接对历史日 `?save=1` 整链重跑不安全：日线 gob 里可能残留盘中未完成的当日 K，历史分支会用脏 Close 覆盖收盘涨幅。

## 目标

1. 对已入选股票计算唯一展示标记，写入 API 与选股 JSON，供 UI 与后续统计。
2. 每个交易日收盘后只更新归档中的 `T0收盘涨幅(%)`，不重跑选股、不刷新日线 gob。
3. 提供按日期的手动补刷入口，用于修正已有归档（如 2026-08-11）。

## 非目标

- 不重拉 / 不删除当日日线 gob。
- 不因标记规则从列表剔除股票（破板+跌停同时命中时仅清空标记）。
- 不做历史 JSON 批量回填标记（旧文件无 `标记` 字段时前端按无标记处理）。
- 不改开盘涨幅过滤阈值、市值门槛、涨停记忆天数等选股门闸。
- 不为 ST 单独设 5% 阈值（现行 ST 涨跌停亦为 10%，与普通股同一套 9.85% / 9.9% 口径）。

## 决策摘要

| 项 | 选择 |
|----|------|
| 标记计算位置 | 后端 `RunT0Selection` 组装阶段（方案 A） |
| 标记字段 | `标记`（string，无标记为 `""`） |
| 多标记展示 | 只保留一条：破板 > 跌停 > 大阴线 |
| 破板且跌停 | 股票保留，`标记=""` |
| ST | 与普通股相同阈值；选股链本就未按名称剔 ST |
| 收盘刷新 | 只改 `T0收盘涨幅(%)`（方案 2） |
| 刷新时点 | 周一到周五上海时区 15:05 起，每天一次 |
| 行情源 | 现有 `fetchT0Realtime`（腾讯），收盘后现价即收盘价 |

## 1. 前日标记

### 输入

对结果组装循环中已有的 `hist`（已剔除选股日当日 K）：

- `prev = hist[-1]`，`base = hist[-2].Close`
- 前日最高涨幅 = `(prev.High - base) / base * 100`
- 前日报开盘涨幅 = `(prev.Open - base) / base * 100`
- 前日收盘涨幅 = 已有 `PrevCloseRet` / 同公式用 `prev.Close`

`base == 0` 或 `len(hist) < 2` 时不打标记。

### 判定

| `标记` 值 | 条件 | UI 颜色 |
|-----------|------|---------|
| `涨停破板` | 最高涨幅 ≥ 9.85 且 收盘涨幅 < 9.85 | 红 |
| `前一天跌停` | 收盘涨幅 ≤ -9.9 | 绿 |
| `前一天大阴线` | 开盘涨幅 − 收盘涨幅 ≥ 4 | 绿 |

### 唯一化

```text
if 涨停破板 && 前一天跌停:
    标记 = ""
else if 涨停破板:
    标记 = "涨停破板"
else if 前一天跌停:
    标记 = "前一天跌停"
else if 前一天大阴线:
    标记 = "前一天大阴线"
else:
    标记 = ""
```

### 落盘

- `T0SelectionResult` 增加 `标记 string \`json:"标记"\``
- 随 `saveT0SelectionArchive` 写入当日 selection JSON
- 无额外网络；候选几十只浮点运算可忽略

### Flutter

- `T0StrategyStock` 解析 `标记`
- `_buildStrategyCard` 在名称旁展示；空串不占位
- 颜色：破板用红色语义色，跌停 / 大阴线用绿色语义色（走 `AppColors`）

## 2. 收盘后刷新归档收盘涨幅

### 行为

进程内 ticker（建议 60s）调用判定函数：

```text
shouldRefreshSelectionClose(now, alreadyDoneForDate) ==
  weekday ∈ {Mon..Fri} AND
  上海时区 minutes ≥ 15*60+5 AND
  当日归档存在 AND
  当日尚未刷新成功
```

命中后执行 `refreshSelectionCloseRet(tradeDate)`：

1. 读取 `t0_selection_{date}.json`
2. 对 `results` 中股票构造腾讯符号，调用 `fetchT0Realtime`
3. 对每条结果：
   - `prevClose`：腾讯昨收 > 0 则用之，否则用归档 `前一交易日收盘`
   - `closePx`：腾讯现价（收盘后即收盘价）
   - 若 `closePx <= 0` 或 `prevClose <= 0`：**保留原 `T0收盘涨幅(%)`**，打 Warn 日志
   - 否则写入 `round2((closePx - prevClose) / prevClose * 100)`
4. 更新 `saved_at`、新增 `close_updated_at`（RFC3339）
5. tmp + rename 原子写回

**明确不改**：股票名单、开盘涨幅、涨停日期、MA20、成交额、前收、标记、其它字段。

### 幂等

- 归档结构增加可选字段 `close_updated_at`
- 当日该字段非空则视为已刷新，ticker 跳过
- 服务 15:05 之后才启动：若当日归档存在且 `close_updated_at` 为空，启动后第一次 tick 补刷

### 手动入口

在 `/api/t0-selection` 增加查询参数，例如 `refresh_close=1`（可与 `date=` 组合）：

- 强制执行一次 `refreshSelectionCloseRet`，忽略「已刷新」短路（便于修脏数据）
- 返回更新后的归档摘要（date / count / close_updated_at / 成功更新条数 / 保留旧值条数）

### 性能

| 项 | 开销 |
|----|------|
| 频率 | 每交易日 1 次（+ 可选手动） |
| 网络 | ~30 只 × 1 次腾讯批量请求 |
| 磁盘 | 读改写一份数 KB～数十 KB 的 JSON |
| 日线 gob / 全市场选股 | 不触发 |

## 3. `T0收盘涨幅(%)` 口径说明（现状，本设计不改计算式）

```text
T0收盘涨幅(%) = (T0当日价格 - 前收) / 前收 × 100
```

- 盘中正式选股：价格多为腾讯现价，首次归档为盘中快照。
- 收盘刷新后：价格为腾讯收盘后现价，归档变为真收盘涨幅。
- 默认无 `save=1` 时不会因 App 刷新覆盖 JSON；本设计的收盘刷新是唯一自动覆盖收盘涨幅的路径。

## 4. 验收标准

1. 新选股结果 JSON 含 `标记`；同时破板+跌停的样本 `标记` 为空且仍在列表中。
2. Flutter 主板策略卡片按红/绿显示唯一标记；无标记无多余占位。
3. 交易日 15:05 后服务运行时，当日归档 `T0收盘涨幅(%)` 与腾讯收盘涨幅误差在合理舍入内（建议抽检 |Δ| < 0.15%）；`close_updated_at` 有值。
4. 行情缺失个股保留旧收盘涨幅，不出现被写成 `0` 的误伤。
5. 手动 `refresh_close=1&date=2026-08-11` 可修正 8 月 11 日归档，且名单与开盘涨幅不变。
6. 单元测试覆盖：标记唯一化、破板+跌停清空、收盘刷新补丁函数、15:05 窗口判定。

## 5. 实现顺序建议

1. `pickPrevDayTag` + 单测 → 接入 `T0SelectionResult` / `RunT0Selection`
2. Flutter 解析与卡片展示
3. `patchCloseRet` / `shouldRefreshSelectionClose` + 单测 → ticker + `refresh_close` 参数
4. 手动刷新 2026-08-11 归档并抽检
