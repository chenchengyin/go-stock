# Flutter Mac 运行与空白看盘小组件

## 用户确认的方向

在现有 `trading_app` Flutter 项目内实现，先编译并启动 Mac 主应用，再添加截图所示的 macOS 系统小组件。小组件内容本轮留空，不接行情。用户已明确要求直接实施、逐步验证。

## 方案

- Flutter/Dart 保留现有主界面和 Go API 客户端。
- 在现有 `macos/Runner.xcodeproj` 增加 SwiftUI + WidgetKit extension target，嵌入同一 `.app`。
- 小组件支持小、中、大尺寸，使用系统背景，显示空白占位，不包含虚构行情、定时行情任务或数据共享层。
- 主应用保留现有标识 `com.colin.tradingApp`，扩展使用其子标识；原有 Android/Web 行为不变。
- 本机先用本地 Go 服务验证网络连通；不修改现有生产服务和数据库。

## 已讨论的其他路线

独立原生项目会拆分现有产品；置顶小窗不是此次选定的系统组件。用户选择在 Flutter Mac 应用内嵌入原生扩展。

## 验收顺序

1. 补齐本机构建依赖与必要的 Mac 网络权限，编译 Flutter Mac，实际打开登录界面。
2. 加入空白 WidgetKit 扩展，验证构建、嵌入、签名、系统注册和可添加性；确认 App 仍能启动。

## 限制

不验证账户内交易功能，不自动登录，不实现行情、持仓、通知或后台运行。本地调试签名与日后正式分发签名分开记录。若系统拒绝无开发者证书的组件，保留完整构建并如实记录具体原因。
