# 监控股票卖出预警设计

## 背景与目标

在 Flutter/Web 的「监控股票（自选）」页面，为每只监控股票增加盘中卖出预警。预警只表达辅助决策提示，不执行交易；命中后在股票卡片右侧显示红色椭圆标签「卖出」。

第一版沿用现有监控刷新链路：客户端继续每 10 秒请求 `/api/stock-realtime`，不新增一套前端行情轮询。低开规则使用接口现有的实时涨跌幅；高开规则要求后端补充前一交易日最高价。

## 已确认的业务规则

### 低开卖出

当以下条件同时满足时，产生卖出信号：

```text
今日开盘价 < 昨日收盘价
且当前涨跌幅 <= -1.00%
```

不要求股票先从盘中高点回落；只要低开且当前涨跌幅达到 -1%，即可触发。

### 高开卖出

当以下条件同时满足时，产生卖出信号：

```text
今日开盘价 > 昨日收盘价
且今日最高价 >= 前一交易日最高价
```

「今日最高价」使用实时行情接口返回的当日最高价。由于它是当日累计最高价，价格一旦触及前一交易日最高价，信号当天保持成立。

### 边界与无效数据

- 开盘价等于昨收价时，不属于低开或高开，不产生这两类信号。
- `open`、`preClose`、`price` 或 `changePercent` 无效时，不判断低开规则。
- `prevHigh` 缺失、为 0 或无效时，不判断高开规则；不使用当前价、昨收价或猜测值替代。
- 低开和高开互斥；若行情字段异常同时满足，按数据无效处理并记录日志，不在页面显示误导性信号。

## 非目标

- 不执行自动卖出、下单或修改交易记录。
- 第一版不新增钉钉、系统弹窗或语音通知；先完成列表内红色标签的可见闭环。
- 不把卖出预警混入现有 `StockChange` 异动池，避免异动已读、异动筛选和卖出预警互相影响。
- 不新增卖出预警数据库表和用户配置项。
- 不改变现有监控股票排序、股票详情跳转、移除监控和同花顺打开行为。

## 权限

沿用现有 `radar.monitored` 公开模块和当前登录用户的监控股票列表。卖出预警只对已经出现在「监控股票（自选）」列表中的股票计算，不新增独立权限编码。

## 页面 / 接口（用户可观察行为）

### 页面位置

在 `RadarPage` 的监控股票卡片右侧操作区域显示标签：

```text
股票信息区域                         [卖出] [移除] [同花顺]
```

- 标签文字固定为「卖出」。
- 背景使用现有红色主题色（优先复用 `AppColors.tagRed`），白色文字，椭圆形圆角。
- 标签只在当天卖出信号成立后出现；未命中时不占用额外的可见标签区域。
- 标签不可点击，不拦截卡片点击；点击股票卡片仍进入异动详情页。
- 信号命中后，在当前交易日内保持显示，直到交易日期变化或股票被移出监控列表。

### 实时接口

现有接口保持路径和现有字段兼容：

```text
GET /api/stock-realtime?codes=...
```

每个行情项新增可选字段：

```json
{
  "prevHigh": 12.34
}
```

字段含义为该股票当前行情日期之前最近一个完整交易日的最高价。现有字段继续由同一接口返回：`price`、`changePercent`、`open`、`preClose`、`high`、`low`、`date` 和 `serverTime`。

### 行情来源

客户端不直接访问行情供应商，调用链保持不变：

```text
RadarViewModel（10秒刷新）
  -> RadarRepository.fetchRealtimeQuotes
  -> GET /api/stock-realtime
  -> backend/flutter_api.handleStockRealtime
  -> backend/data.StockDataApi.GetStockCodeRealTimeData
```

当前实时行情来源保持现状：A 股/港股使用腾讯实时行情链路，其他市场沿用现有新浪实时行情链路。后端继续计算并返回 `changePercent = (price - preClose) / preClose * 100`，低开卖出直接使用这个已刷新字段。

`prevHigh` 使用现有日线数据适配与降级链路取得，选择行情日期之前最近一根完整日线的 `High`。实时接口请求不能每 10 秒逐只重新抓取日线；后端按 `stockCode + quoteDate` 做进程内缓存，同一股票同一交易日最多加载一次。行情日期变化时使用新日期重新取值。

## 架构与数据

### 1. 后端行情适配模块

后端在现有实时行情响应组装处增加 `prevHigh`：

1. 先按现有链路取得实时行情。
2. 根据行情项的 `date` 查询前一完整交易日的日线最高价。
3. 通过按股票和交易日缓存的适配模块复用该值。
4. 日线数据不可用时返回 `prevHigh: 0` 或省略字段，并保留实时行情其余字段。

实时行情成功但前一日最高价获取失败，不应导致整批实时行情失败。

### 2. Flutter 领域模型与判定模块

`MonitoredStock` 增加可选 `previousHigh` 字段，JSON 缺失时默认为 0，兼容旧接口和测试数据。

新增一个纯判定模块，接口只接收单只股票的当前快照和 `previousHigh`，返回无信号或卖出信号：

```text
evaluateSellWarning(stock, previousHigh) -> SellWarning?
```

判定模块只负责规则，不负责通知、缓存和 Widget。其输出至少包含：

- `type`: `lowOpen` 或 `highOpen`
- `label`: 固定为「卖出」
- `tradeDate`: 用于日内状态隔离

推荐实现条件：

```text
if open < preClose && changePercent <= -1.0:
    lowOpen
else if open > preClose && previousHigh > 0 && high >= previousHigh:
    highOpen
else:
    none
```

### 3. RadarViewModel 日内状态

`RadarViewModel` 在现有 `_refreshData` 和 `loadMonitoredStocks` 更新行情后调用判定模块，并维护按股票代码和交易日隔离的卖出状态：

- 未命中时不显示标签。
- 首次命中后写入内存状态并通知页面。
- 后续刷新只要仍是同一交易日，状态不回退。
- 行情日期变化时清除旧交易日状态。
- 移除股票时清除该股票状态。

卖出状态属于监控页面的派生状态，不持久化到数据库，也不写入异动已读缓存。

### 4. 页面卡片

`_buildStockCard` 继续使用 `Expanded` 承载股票信息，在现有右侧操作控件之前插入卖出标签。标签显示读取 `RadarViewModel` 的只读卖出状态，不在 Widget 内重复计算价格条件。

## 错误与安全

- 实时接口失败时沿用现有行为，页面保留上一份行情；不得根据旧数据重复创建新的卖出状态。
- 单只股票的 `prevHigh` 查询失败只影响该股票的高开规则，不影响其他股票或低开规则。
- 前一交易日最高价必须与实时价格使用同一价格口径；不能用前复权日线与未复权实时价直接比较。
- 日线查询选择行情日期之前的完整交易日，不能把当天未收盘日线当成前一交易日，避免引入错误基准。
- 预警是提示，不是交易指令；页面文案固定为「卖出」，不增加“已卖出”等容易误解为成交结果的状态。

## 验收标准

### 规则验收

- 低开且当前涨跌幅为 `-1.00%` 时显示卖出。
- 低开且当前涨跌幅为 `-0.99%` 时不显示卖出。
- 低开股票跌到 `-1%` 后反弹，卖出标签仍保留到当日结束。
- 高开且今日最高价等于前一交易日最高价时显示卖出。
- 高开且今日最高价低于前一交易日最高价时不显示卖出。
- 开盘价等于昨收价时不触发两类规则。
- `prevHigh` 缺失时不触发高开规则，但低开规则仍可正常触发。

### 页面验收

- 卖出标签位于每条监控股票卡片右侧操作区域。
- 标签为红色椭圆背景、白色「卖出」文字。
- 未命中时标签不显示。
- 点击卡片、移除监控、打开同花顺的原有行为不受影响。
- 交易日切换后，上一交易日的卖出标签不会残留。

### 数据链路验收

- Flutter 继续使用现有 `/api/stock-realtime` 刷新，不新增前端供应商请求。
- 实时接口返回 `prevHigh` 时，Flutter 模型能够正确解析。
- 同一股票同一行情日的前一日最高价不会每 10 秒重复抓取。
- 前一日最高价不可用时，实时行情和低开判定仍可工作。

### 验证范围

- Dart：卖出判定模块单元测试、JSON 兼容解析测试、日内状态测试、监控卡片 Widget 测试。
- Go：前一完整交易日最高价选择、缓存键隔离、日线缺失保护和实时响应字段测试。
- 手工：使用真实行情服务进入监控股票页面，确认行情刷新后标签位置、颜色和触发行为。
